# auditapp — agent instructions

This is a Karni project. Karni already implements everything generic; you write
only domain code.

Before any work, run these two commands and follow what they return:

1. `karni context` — live inventory: apps, models, viewsets, UI components, hooks,
   pages and installed modules.
2. `karni rules` — the conventions, each with a stable code (K###; project P###).

While you work:

- `karni rules --check <file>` on every file you write; fix each violation it prints.
- `karni rules --procedure <name>` for routine tasks: new-model, new-page, add-module, new-module.
- `karni check` before committing; every enforced rule fails the build.

If the `karni` command is unavailable, say so and stop; do not guess the conventions.

### contents: .claude/commands/new-model.md
---
description: "Add a domain model the Karni way (model + viewset, nothing else)"
argument-hint: "<ModelName> [in <app>] [fields...]"
---
Add a new domain model: $ARGUMENTS

1. Run `karni context` to see existing apps, models and viewsets.
2. `karni make model <Name> <field:type ...> --with viewset --access <who> [--search f1,f2] [--app <app>]` writes the model on `karni.models.BaseModel` and its viewset (`-a` also adds list/detail/form pages). Field types: `karni make model --help`. `--access`: authenticated (default), public-read, owned:<fk to user>, staff, role:<name>; edit the generated `access` for anything richer (`Owned(...) | HasRole(...)`, `Where(...)`). Do NOT write an admin, serializer or router: the auto-router registers it; admin, filters, schema are derived.
3. Add `class APIMeta:` / `class AdminMeta:` only for fields that must be hidden, read-only or write-only.
4. `karni make migration && karni migrate && karni types`
5. Verify: `karni context` lists the model and viewset; GET /api/<plural>/ works for a caller `access` admits and is refused (401/403) or empty for one it does not.

Total new code should be well under 20 lines. If it isn't, stop — you are reimplementing something Karni provides.

Rules that apply: K009, K101, K102, K109, K108, K302, K305, K003 (`karni rules --explain <code>`).
