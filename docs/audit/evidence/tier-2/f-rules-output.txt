### karni rules --explain K106
K106 [backend, error] Never write a Meta-only `ModelSerializer`; `BaseViewSet(model=X)` generates it.
Why: A redundant serializer silently diverges from the generated one.
Fix: Delete it; customise via APIMeta or override get_serializer_class().
Enforced by: redundant-serializer

### karni rules --explain K109
K109 [backend, error] Every `BaseViewSet` declares `access = Access(read=..., write=...)` (`create=` defaults to `write`), built from `Owned("<fk to user>")`, `HasRole(...)`, `Authenticated()`, `Public()` and `Where(lambda request: Q(...))` combined with `|` / `&`. Reads are public only when you write `Public()`. A viewset without `access` denies every request; `Unscoped(reason=...)` is the explicit opt-out.
Why: One declaration compiles into both the request gate and the row filter, so neither can be forgotten; a forgotten permission class fails open silently.
Fix: Add `access = Access(read=..., write=...)` (e.g. write=Authenticated()).
Enforced by: viewset-access
