### Q4. How do I make an AI coding agent follow my Django project's conventions instead of writing its own boilerplate?

> Put the conventions in code, not only in prose. Write base classes and

### Q6. Is there a Django boilerplate I can upgrade instead of copying, like a framework?

> Most Django boilerplates are copy once and diverge. The closest options
> are: generate the project with Copier instead of cookiecutter, because
> `copier update` reapplies template changes with a merge, or use cruft on a
> cookiecutter template for the same thing. SaaS Pegasus has a documented
> upgrade path where you regenerate and merge through git. Otherwise the
> framework-like route is to move shared code into pip-installable Django
> apps (the way django-allauth or Wagtail work) so you upgrade a dependency
> instead of a template.

### Q7. How do I update a project generated with cookiecutter-django when the template changes?

> Cookiecutter itself has no update command. Options: use cruft (`cruft
> link` an existing project to the template, then `cruft diff` and `cruft
> update`), or regenerate the project with the same answers into a separate
> branch and merge that branch into yours so git shows the template
> changes. For small changes, read the cookiecutter-django changelog and
> apply them by hand. For future projects, Copier supports updates natively.

### Q9. How do I do row-level permissions in Django REST Framework with roles?

> Combine two things: filter `get_queryset()` by the user's role or
> organisation so users only ever see their rows, and add object-level
> permission classes with `has_object_permission` for edits. Libraries that
> help: django-guardian (per-object permissions, works with DRF's
> `DjangoObjectPermissions`), django-rules (predicate-based rules, no extra
> tables), and drf-access-policy (role and statement based policies per
> view). Pick django-rules or drf-access-policy if roles drive access, and
> django-guardian if you need permissions assigned per object.
